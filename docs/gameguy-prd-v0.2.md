# GameGuy 产品需求与实施方案

> **历史版本，已被 v0.3 取代。** 本文保留旧插件模式的需求基线，不代表当前产品结构或实现状态。当前以 [独立产品 PRD v0.3](../gameguy-prd-v0.3.md)、[架构](architecture.md) 和 [验证记录](verification.md) 为准。

- 版本：v0.2（三个独立游戏插件的 MVP 草案）
- 日期：2026-10-22
- 基础框架：DeepSeek Harness（DSH）
- MVP：龙虾杀、Minecraft（Mineflayer）、明日方舟（MAA）三个独立插件
- 状态：已核对公开文档与本地官方龙虾杀 Skill；未安装、运行或联调这些后端。指标、接口设计和排期均为建议。

## 1. 产品结论

**GameGuy 是基于 DSH 的游戏 Agent 平台：平台提供公共能力，每个游戏通过独立插件接入。**

MVP 验证三种接入方式：

| 游戏插件 | 复用能力 | Agent 的职责 | 插件的职责 |
|---|---|---|---|
| 龙虾杀 | 官方 gameplay Skill + ccl  | 读局势、推理、发言、投票 | Skill 加载/宿主适配、网页预览、必要的平台集成 |
| Minecraft | Mineflayer 及必要生态组件 | 目标拆解、规划、异常调整 | 结构化状态、可取消动作、世界连接、结果验证 |
| 明日方舟 | MAA 库接口与资源 | 理解日常需求、生成配置、解释结果 | 类型化任务封装、设备连接、回调、资源限制 |

**龙虾杀接入最轻，应作为第一个纵向打通的插件。** 已有 Skill 能玩，不应把自主移动、游戏规则引擎、匹配系统重新列为开发项。接入能玩和策略很强是两件事；首期不以胜率验收。

三个插件全部属于 MVP。

## 2. 用户与核心体验

### 2.1 目标用户

- 游戏 Agent 爱好者：让 Agent 玩龙虾杀、在 Minecraft 中执行目标。
- 二游玩家：通过自然语言组织日常自动化，减少重复配置。
- 插件开发者：包装已有游戏接口，不重复实现会话、模型和任务展示。

首期本地优先，由用户提供游戏、合法账号、客户端/模拟器和模型配置。

### 2.2 示例需求

- “用这个人设玩一局龙虾杀。”
  - 系统自动开局，并在 DSH 网页预览中展示当前对局，用户无需索取或手动打开观战链接。
- “加入这个好友房；本局结束先停下来，不自动再排。”
- “进入我的 Minecraft 测试服务器，收集木头，做一把石镐。”
- “明日方舟刷指定关卡 5 次，不吃药、不用源石，然后换班、收信用和日常奖励。”
- “按已保存的基建方案换班；信用商店只领取，不购物。”
- “跑一个已支持主题的肉鸽，最多启动 3 次，达到时长上限就停止。”

以上为产品目标示例，不是已经完成的功能演示。

### 2.3 主流程：目标驱动，不要求用户先安装插件

**用户提出游戏目标 → Agent 从插件市场发现并安装/启用对应插件 → 根据插件说明检查环境、通过对话完成配置 → 验证连接 → 执行任务，右侧预览展示游戏画面 → 返回结果 → 按用户要求设置 schedule，后续到点自动执行。**

已安装且配置有效时，直接复用，跳过安装与重复询问。插件列表和配置界面是可选管理入口，不是首次使用的必经路径。首次安装第三方代码按可信来源与用户授权策略处理；“自动安装”不等于安装任意搜索结果或绕过宿主审批。

#### 明日方舟收菜示例

1. 用户：“帮我玩明日方舟收菜。”
2. Agent 检查插件是否已安装；若未安装，从受信任插件市场选择兼容的明日方舟插件，按安装授权策略下载、校验并启用。
3. Agent 读取插件 Skill/配置 schema，检测设备与依赖；仅询问无法安全推断的关卡、换班方案和资源偏好，采用明确展示的保守默认值。
4. 配置验证通过后，按用户委托通过插件执行收菜；右侧网页预览显示游戏画面与画面更新时间，聊天/状态区显示执行进度和停止入口。
5. 执行结束返回实际完成项、失败项和可验证结果。
6. 用户：“以后每天早上 8 点按这套方案收菜。”Agent 展示时区、执行设备、保存模板、资源限制和下次执行时间，按用户明确授权保存 schedule。后续无需每天再发消息。

界面至少提供：聊天、右侧游戏画面预览、状态/进度与停止入口、结果摘要，以及按需打开的插件、配置和 schedule 管理。龙虾杀展示官方观战网页；明日方舟展示插件输出的设备画面；Minecraft 首期保留结构化状态，画面适配独立声明能力，不假称 Mineflayer 自带渲染器。

## 3. MVP 范围与非目标

### 3.1 P0 范围

1. 三个可独立安装、启用、升级和禁用的游戏插件。
2. 公共实例管理、资源占用、运行记录、取消、风险策略和结果展示。
3. 龙虾杀完成一局的接入闭环，支持恢复已有参与、退出，以及在 DSH 网页预览中自动展示对局。
4. Minecraft 连接指定版本测试服务器，完成有限的移动、采集、合成任务。
5. MAA 五类封装：刷理智、基建换班、信用相关、日常领取、肉鸽。
6. 模型可见的状态与结果；不能只在后台日志中记录关键事实。
7. 单游戏实例单执行者；安装/启用其他插件不应争夺实例控制权。
8. 最小可信插件市场与按需自动安装：至少可发现、下载、校验和启用三个 MVP 插件。
9. 明日方舟右侧游戏画面预览，不仅展示 MAA 日志。
10. 对话创建、查看、修改、暂停、删除 schedule，按已保存配置执行收菜并记录结果。

### 3.2 首期不做

- 任意游戏零适配、统一视觉控制所有游戏。
- 商业化插件商城、付费结算、开放上传审核体系、任意第三方代码安全沙箱、云端多租户托管。首期包含官方/受信任来源的最小插件市场，不包含完整商业生态。
- 所有 Minecraft 版本、所有公共服务器、完整生存通关。
- 全部 MAA 任务、所有肉鸽主题/结局、任意关卡必过。
- 付费购物、充值、源石恢复、自动抽卡。
- 龙虾杀自研控制器、多账号代打、胜率保证。
- 平台重启后所有游戏无损续跑。

## 4. 插件边界与发布形态

### 4.1 推荐包结构

| 包（拟定名称） | 所有权与边界 |
|---|---|
| @gameguy/core | 公共协议、实例注册、运行记录、资源锁、风险策略，以及插件安装与 schedule 的公共集成；不含游戏实现 |
| @gameguy/plugin-clawclaw | 官方 Skill 资源、对局 preset、网页预览与必要的宿主适配 |
| @gameguy/plugin-minecraft | Mineflayer 连接、游戏状态、动作、验证、preset |
| @gameguy/plugin-arknights | MAA 连接、库接口 worker、五类任务、回调、preset |
| @gameguy/bundle | 可选的一键组合安装与默认 profile；不是大一统游戏实现 |

可以放在同一个 monorepo，但必须保持独立包、独立依赖、版本和测试。只装龙虾杀，不要求安装 Mineflayer、MAA 或模拟器。

### 4.2 每个游戏插件负责

- 声明游戏标识、版本、支持能力、DSH/core 兼容范围、支持平台、后端依赖与安装权限，供 Agent 发现、选择和安装。
- 连接检查、配置校验、实例创建与销毁。
- 提供 Skill/提示资源和 preset，按需注册模型工具；纯 Skill 接入不强制新增工具。
- 定义游戏原生状态、动作、回调解析、验证和取消语义。
- 输出公共运行/事件记录，同时保留必要的游戏特有扩展。
- 提供诊断、故障恢复提示、兼容矩阵与测试。
- 按能力声明提供游戏画面预览源、对话配置 schema、可复用任务模板与是否支持定时执行；不要求每个游戏都支持无人值守。

平台 core 不用按游戏名称 switch/case 分发业务。新游戏通过注册能力接入；缺少某插件时其他插件仍可正常使用。

### 4.3 统一什么、不统一什么

统一生命周期、实例归属、运行状态、权限、事件信封和结果摘要。**不强行统一所有游戏动作，也不要求所有游戏都变成轮询任务。**

- 龙虾杀：实时事件驱动的参与/对局。
- Minecraft：规划驱动的结构化交互。
- MAA：任务链驱动的长时间自动化。

“暂停”是可选能力。不能暂停的后端只提供停止；停止不能撤销已完成的游戏动作。

### 4.4 最小可信插件市场（P0）

市场是机器可查询的插件目录与受信任包源，首期上架三个 MVP 游戏插件即可；不必先建设完整商店 UI。目录提供游戏别名/能力、包标识、发布者、版本、支持平台、兼容范围、依赖、权限、下载位置与可信完整性元数据。Agent 只能选择已配置可信目录中的条目，不依据网页提示随意下载安装代码。

安装流程：检测已有包 → 查找兼容条目 → 按授权策略确认新代码与依赖安装 → 下载/校验 → 安装/启用 → 健康检查 → 加载 Skill 与配置能力。校验应绑定可信目录中的摘要或可验证签名，而不是只信下载包自报的摘要。安装失败不留半启用状态，重复请求不重复安装；已有可用版本不在每次 schedule 时自动升级。

“打包好的插件”包括接入代码、Skill、配置/能力描述与安装清单，不等于打包游戏本体、账号与模拟器。MAA 等二进制/资源的随包分发或首次下载须符合各自许可，并在安装清单中声明。

## 5. 公共功能需求

| ID | 需求 | P0 验收 |
|---|---|---|
| FR-01 | 插件市场发现与自动安装 | 根据用户游戏目标发现兼容可信插件，按授权下载、校验、启用；已安装则复用；一个后端缺失不阻止其他插件启动 |
| FR-02 | 实例与控制权 | 绑定实例、账号/角色/设备范围；拒绝同实例并发控制 |
| FR-03 | 工具与 preset 隔离 | 当前游戏只暴露相关工具；服务端再次校验实例归属 |
| FR-04 | 对话配置、委托与预览 | Agent 检查环境、询问缺失信息、生成并校验配置；执行前展示目标、次数/时长、资源消耗和停止条件 |
| FR-05 | 状态与事件 | 关键事件进入模型可见记录和 UI；关联实例与运行 |
| FR-06 | 取消与接管 | 前端和模型均可请求停止；回报实际停止状态 |
| FR-07 | 风险限制 | 参数校验在插件/策略层执行，不依赖提示词自觉 |
| FR-08 | 结果与证据 | 区分流程结束、目标成功、部分成功和无法验证 |
| FR-09 | 记录与恢复 | 保存配置和摘要；重启后重新诊断，不假装外部世界已恢复 |
| FR-10 | 故障诊断 | 显示缺少依赖、连接失败、后端版本不兼容和人工处理建议 |
| FR-11 | 游戏画面预览 | 龙虾杀自动展示观战页；明日方舟右侧展示设备画面，标记更新时间、断连与过期状态 |
| FR-12 | 对话式 schedule | 创建、查看、修改、暂停、删除计划；保存时区、模板、实例、资源授权，显示下次执行与每次结果 |

P1：高级模板管理、多渠道通知、更丰富游戏 UI、多实例管理、开放插件生态。基本收菜模板保存、schedule 与站内失败/人工处理提醒属于 P0。这里描述产品功能，不表示本次创建任何实际定时执行。

## 6. 龙虾杀插件：复用 Skill，而不是重做游戏 Agent

### 6.1 接入判断

官方快速开始已给出 CLI + Skill 安装、开局、恢复与观战流程；明确提到 Claude Code、OpenClaw、Pi。普通 Agent 能通过 Skill 玩，证明主要游戏交互已经可复用。

**DSH 的重点是薄宿主适配，不是游戏驱动开发。** 官方宿主支持列表不等于 DSH 已被验证兼容，仍需小原型确认事件到 Agent 回合的链路。

### 6.2 最小实现：Skill 原生接入

1. **Skill 加载与宿主适配**：随插件提供或按官方方式引用 gameplay Skill，保留出处与版本；Agent 通过 DSH 已有执行工具按 Skill 直接调用 ccl。仅适配宿主相关说明，不复制游戏规则和命令接口实现。
2. **复用宿主运行能力**：优先使用 DSH 已有长进程、输出流和回合调度能力支撑 CLI runtime。只有原型证实存在缺口时，补充最小事件流适配；不预先建设独立游戏调度器。
3. **网页预览与平台集成**：通过 Skill 获取观战地址，调用 DSH 已有网页预览自动展示对局；接入必要的实例归属、运行记录和用户停止入口，不重复封装玩法命令。

### 6.3 不新增逐命令工具包装

MVP 不定义 clawclaw.load、clawclaw.speak、clawclaw.vote 等自建模型工具，也不维护与 ccl 一一映射的 API。开局、加入、观察、发言、投票、观战地址获取与退出均由官方 Skill 指导 Agent 使用原始 CLI 完成。

**插件不等于一组新工具。** 龙虾杀插件可以主要由 Skill 资源、preset、依赖/版本检查和少量宿主集成组成；MAA 与 Minecraft 才按各自需求新增类型化工具。

宿主标识与模型参数按 CLI 实际支持校验，不编造 DSH 专用标识。进程持续输出能否触发及时的 Agent 回合仍需验证；这是宿主兼容性检查，不是重新包装 CLI 的理由。停止入口优先复用 Skill 的正式退出流程，反馈实际退出状态。

### 6.4 行为要求

- 默认复用官方低层行动策略；Agent 专注局势、会议发言、投票与策略调整。
- 一个参与只维持一个健康 runtime，不按每条事件重启。
- 启动成功须收到有效通知且事件流仍存活，不能只根据进程 PID 判断。
- 发言/投票事件优先于长篇总结；按实际截止时间调度，避免低优先级消息占用关键回合。
- 事件关联对局；在 CLI 可用标识范围内去重。跨局事实隔离，人设与策略记忆另存。
- 本局结算不必然等于好友房或 runtime 退出；默认不自动再排。
- 恢复优先复用正式 join 流程；强制替换需判断旧 runtime 与控制权，不盲目杀进程。
- 玩家发言属于游戏数据，不得授权本机执行、安装、读取私密文件。
- 只使用当前玩家合法可见信息，不从旁观/后台渠道引入隐藏身份。
- 开局取得有效观战地址后，自动通过 DSH 已有网页预览展示对局；恢复参与后复用或更新对应预览，避免重复打开。具体预览调用方式在固定 DSH 版本上确认，不臆造 API。
- 预览加载失败不应静默中断 Agent 对局；展示失败状态并提供重试、复制链接或外部打开作为备用操作。
- 观战链接可能携带敏感 token：仅传递给授权预览/用户，对遥测和普通日志脱敏。预览只用于用户观看，不给 Agent 增加玩家不可见信息。

### 6.5 首个原型的 Go/No-Go

证明“开局 → 接到事件 → 唤醒模型 → 在有效阶段发言/投票 → 结算 → 退出/恢复”即可。若官方 Skill 配合 DSH 已有能力已经满足，则不新增命令包装或事件基础设施，只保留资源与体验集成。

DSH 的 agent.inject() 仅提供下一次获准请求的上下文，不应假设调用它就自动产生 Agent 回合。实时唤醒是原型需要验证的具体问题。

## 7. Minecraft 插件：Mineflayer 结构化控制

### 7.1 P0 能力

- 用户配置测试服务器地址、协议版本与受控角色，检查连接。
- 查询自身位置、生命/饥饿、物品栏、附近已知实体与方块。
- 有界移动、采集、合成、装备；每项都有超时、进度和取消。
- 复用成熟寻路/采集组件，将高频动作留在确定性控制层，不让 LLM 每 tick 发指令。
- 完成两条验收路线：采集指定数量木头；在具备条件的测试世界制作石镐。
- 通过物品栏/世界状态核验结果，不把“动作返回”当作目标完成。

### 7.2 边界

锁定一个 Java 版测试组合及组件版本。环境不满足时解释缺少材料、路径不可达或工具不足；不保证任意世界完成。断连、死亡、卡路需要有限重试和重新观察。

破坏方块、丢弃物品、攻击和大范围建造默认受限；公共服务器仅在用户授权且服务器规则允许时使用，不做绕过反作弊。

## 8. 明日方舟插件：MAA 五类任务均纳入 MVP

### 8.1 实现路径

使用 MAA 库 API，而非驱动 MAA 桌面 GUI。DSH TypeScript 插件通过本地 worker 包装库接口；语言可选 Python/C++，以兼容性原型决定。MVP 先支持一个经过测试的 ADB 连接组合。

主要生命周期：加载资源 → 创建实例与回调 → 异步连接 → 添加类型化任务 → 启动 → 接收回调 → 核验/停止 → 销毁。

已核对 API 包括 AsstLoadResource、AsstCreateEx、AsstAsyncConnect、AsstAppendTask、AsstSetTaskParams、AsstStart、AsstStop、AsstRunning、AsstConnected、AsstGetImage、AsstDestroy、AsstGetVersion。

### 8.2 P0 能力与限制

| 用户场景 | MAA 任务 | MVP 封装与验收边界 |
|---|---|---|
| 刷理智 | Fight | 测试关卡、有限次数、时长、掉落统计；默认不吃药、不吃临期药、不用源石 |
| 基建换班 | Infrast | 已支持设施和用户选定的测试方案；报告换班结果、缺人等异常 |
| 信用相关 | Mall + 部分 Infrast 配置 | 访问好友、信用领取及支持的线索流程；购物单独显式开启 |
| 日常领取 | Award | 日常/周常与邮件领取；活动领取仅承诺测试版本支持范围 |
| 肉鸽 | Roguelike | 一个测试主题，有限启动次数和时长；基础刷分/后端支持的投资模式 |

五类都为 P0，但肉鸽是**有界调用成熟后端**，不是开发一个全主题、全结局自主肉鸽 Agent。

### 8.3 参数与消费策略

- Fight 必须设置有限次数，不能继承超大默认次数；medicine、expiring_medicine、stone 默认均为 0。
- 掉落阈值由 MAA 按任一阈值满足即可停止的 OR 语义处理，不能误称所有阈值都达到。
- 基建方案可通过对话选择模板、生成或修改，并保存到插件管理的配置目录；导入已有文件时须来自用户授权的允许路径，模型不能任意读本机文件。部分参数不支持运行中更新，应停止后重建。
- Mall 默认 shopping=false。信用购物与付费购物分开：用户可授权信用购物，仍禁止付费消费。
- buy_first 是优先列表，不是严格白名单。默认关闭 force_shopping_if_credit_full，避免满信用时覆盖黑名单行为。
- 不承诺仅靠现有 Mall 参数实现严格单次支出上限或白名单外绝不购买；此类要求未能安全实现时，应拒绝自动购物。
- 信用相关的 credit_fight 会消耗理智，应单独披露并授权。
- Award 的 recruit 参数涉及限定池免费单抽，不是普通自动公招；本 MVP 默认关闭抽卡相关能力。
- 肉鸽配置需明确主题、模式、队伍、核心干员等支持范围；有限 starts_count、外部时长上限和失败重试。
- 肉鸽局内源石锭不等于付费源石，不能混用资源策略。
- “等”留作后续扩展口：自动公招、作业、仓库识别等不自动计入本期承诺。

### 8.4 回调与结果

映射连接、任务链开始/完成/错误/停止、子任务进度和附加信息；保留后端任务 ID。AllTasksCompleted 的 finished_tasks 表示已执行任务，不证明所有用户目标成功。

区分：后端流程结束、业务目标已验证、部分完成、未知。刷理智展示实际执行与已观察掉落；基建展示已处理设施和错误；领取与肉鸽仅展示可证实结果。回调协议可能随版本变化，需锁定库、资源与解析器版本并测试。

### 8.5 对话式首次配置与后续修改（P0）

用户表达目标，Agent 负责将自然语言转换为插件可校验、可保存的配置。首次配置不要求用户掌握 ADB 地址、MAA 参数或手写基建 JSON。

1. **检查环境**：通过插件受限诊断接口检查 MAA 依赖、资源版本与可发现的 ADB 设备；无法发现时询问模拟器信息或引导用户开启 ADB。不假设所有模拟器都可自动发现。
2. **确认设备与测试连接**：仅一个已授权设备时可选用；多个设备时询问用户。连接测试与必要状态观察通过后才标记就绪，不能仅凭端口存在判断游戏可操作。
3. **配置刷取目标**：接受关卡、次数、材料目标或“理智不足就停”的表达；材料目标只映射到经过维护的支持关卡，不保证自动找到最优关卡。检查资源支持，实际代理指挥可用性在可观察时核验，无法确定则说明。即便以理智不足为停止条件，也保留有限次数和时长兜底。
4. **配置基建**：先让用户按自然语言选择已有测试模板/当前受支持自动换班方式，再按需询问设施、队伍等信息。复杂排班依赖已授权、可获得的干员与设施信息；信息不足时不编造最优排班，不承诺仅凭一句话自动恢复完整干员阵容。
5. **资源策略与确认**：默认不吃药、不用源石、不购物、不抽卡，并设置可见的有限运行上限。只追问影响执行的缺失项；扩大消耗权限必须取得明确授权。源石消费、付费购物与抽卡仍在本 MVP 禁止范围内，不能通过对话开启。
6. **保存与修改**：展示人可读配置摘要，按用户意图保存为收菜模板。区分“仅本次”与“以后默认”；后续可说“以后改刷这个关卡”或“这次最多吃一瓶药”。更新需再次校验，失败保留旧配置；运行中不支持修改的参数在停止/下一次运行时生效。

示例：“帮我配置明日方舟收菜，用已连接的模拟器，刷 1-7，基建用默认测试方案，信用只领取，不吃药，最多半小时。”Agent 检查连接和模板适用性，展示实际步骤与限制；必要信息齐全后按用户委托执行。未明确的参数不得用可能消费资源的猜测补齐。

游戏客户端/模拟器与登录仍需用户提供。可支持环境诊断与安装引导，但系统安装、修改设备设置需相应授权；密码、验证码和扫码登录通过安全交互由用户完成，不要求在聊天中发送密码。对话配置不是绕过登录与设备授权。

### 8.6 右侧游戏画面预览（P0）

明日方舟插件提供设备画面源，平台通过 DSH 网页预览打开受控的本地预览页。首期可采用限频截图刷新，无需先做视频编码直播；必须展示可辨认游戏画面，不用日志面板代替。使用 AsstAsyncScreencap/AsstGetImage 或授权的 ADB 截图路径，实际路径由原型确认，须协调与 MAA 执行的设备访问并测量负载。

画面绑定 instanceId，标记采集时间、连接和运行状态；断连/截图失败显示明确提示。只向授权本地预览提供画面，不将设备画面公开到公网。预览关闭不停止已授权收菜；自动执行可在无预览窗口时运行，用户打开任务后再连接画面。观看不默认获得远程点击控制，交互式接管另行声明能力。

## 9. DSH 集成架构与协议

### 9.1 架构

龙虾杀：用户/DSH UI → 游戏 preset + 官方 Skill → DSH 已有执行工具 → ccl CLI → 游戏；官方观战页面通过 DSH 网页预览展示。

Minecraft / MAA：用户/DSH UI → 会话与游戏 preset → 各自插件工具 → Mineflayer worker / MAA worker → 游戏。

@gameguy/core 为插件提供注册、实例与控制权、风险策略、运行记录、事件和结果服务。复用 DSH 的工具、会话、模型、任务基础能力，不 fork 或依赖具体 Agent loop 内部实现。

### 9.2 公共协议草案

- PluginDescriptor：id、version、compatibility、capabilities、configSchema。
- GameInstance：instanceId、pluginId、connectionState、owner、resourceKeys。
- GameRun：runId、instanceId、goal、limits、status、backendRefs。
- GameEvent：runId/participationRef、instanceId、type、timestamp、priority、payload、dedupeRef（后端支持时）。
- GameResult：executionStatus、goalStatus、completedItems、warnings、evidenceRefs。

运行状态建议：pending、running、waiting_user、stopping、succeeded、partial、failed、cancelled、unknown。连接和会话/参与状态另存，不用一个状态机覆盖所有概念。

取消要等待后端确认或报告 unknown；重试必须检查是否会重复消费、重复发言或重复创建参与。只对具备安全重试条件的步骤自动重试。

### 9.3 必须尊重的 DSH 约束

- DSH 为 developer preview，需要锁定版本并维护兼容测试。
- profile 的插件激活对该 profile 会话生效；preset 控制工具选择不代替服务端授权。
- jobs-local 是进程内执行，不提供平台重启续跑保证。保存记录不等于恢复进程/游戏。
- 会话回放不恢复 Minecraft 世界、MAA 设备状态或龙虾杀参与。
- Host 插件在进程内、位于 workspace sandbox 之外，应视为可信代码。worker 分进程主要解决故障隔离，不宣称是安全沙箱。
- 龙虾杀直接复用 DSH 已有网页预览，不因展示官方观战页面而另建自定义 Client 插件。Host presenter 不自动产生专用 Web 卡片；后续若需自定义游戏卡片/交互面板，再评估 Client 插件。网页预览与自定义 UI 是两种不同需求。
- 外部事件要变成模型可见上下文，并验证触发回合的调度链路，不能只有后台日志。

### 9.4 持久化 schedule 与无人值守收菜（P0）

用户可在对话中创建、查看、修改、暂停和删除计划。保存前显示游戏实例、任务模板、时区、执行时间、下次运行、资源授权、单次次数/时长上限和失败处理。模型只负责理解与配置；实际到点触发由确定性 scheduler 执行，不让模型靠记忆等待时间。

- 优先复用经验证的 DSH 调度能力；若不存在可用的持久化调度，则增加公共 scheduler/本地常驻服务。不得把 jobs-local 当作 scheduler 或跨重启持久任务。
- 保存 schedule、实例、配置/模板版本、时区、启用状态、下一次时间和执行记录。触发后调用同一游戏插件执行入口，默认复用已确认模板，不每次重新问配置。扩大消费或更换设备授权仍需确认。
- 同一实例串行执行；每个触发槽去重。前次未结束时跳过并记录，不堆积队列；失败只允许有限、安全的重试，已消费步骤不能盲目重复。
- 计划与历史持久化，不承诺运行中任务恢复。进程重启后重新加载计划和诊断外部状态；首期默认错过时段不补跑，按下一次时间执行并记录漏跑。
- 本地机器、调度服务、设备与游戏登录必须可用。关闭 UI 时能否继续取决于常驻服务是否运行；首期不承诺关机/睡眠时执行、系统自动唤醒或云端代运行。
- 登录失效、验证码、游戏维护或不兼容更新应暂停本次执行并在平台记录需要人工处理，不绕过验证、不无限尝试。正常完成保存摘要，失败/需介入产生站内提醒。
- 无人值守授权限于指定模板与实例；schedule 本身不是对后续任意命令和任意消费的授权。

## 10. 安全、稳定性与性能

- Minecraft/MAA 新增工具使用明确的 API 范围和 schema 校验，不向模型开放任意 MAA Custom/SingleStep。龙虾杀复用 DSH 已有执行工具的权限机制与可信 Skill，不新增绕过审批的执行接口，不因游戏需要而全局关闭权限控制。Skill 本身不是安全沙箱，游戏聊天不能扩大执行权限。
- 后端认证信息只存本地合适的密钥存储；日志、导出和遥测脱敏。
- 单实例资源锁、心跳与租约失效处理；模型/窗口退出不应留下无人管理的消费流程。
- 默认不无限运行、不无限重试、不无限消耗。可配置时长、次数及明确的停止条件。
- 高频原始事件先做有损/无损分类，合并可合并状态，但不能丢掉会议轮次、行动截止或消费错误。
- 龙虾杀选择足够快的模型与合适的思考模式，依据真实截止时间测量延迟，而非先承诺固定性能。
- 后端掉线应显示 degraded/unknown，不把旧观察当当前事实。
- 自动化可能受游戏条款限制，产品说明支持范围与风险，不规避限制。
- DSH 的 MIT 许可不覆盖 MAA、Mineflayer、CLI、资源及其依赖；发布前分别核对当前 LICENSE、分发和归属要求。
- 龙虾杀存在可用官方 Skill/CLI，不据此宣称其客户端或服务端代码开源。

## 11. MVP 验收清单

### 平台

- 从未安装明日方舟插件的环境开始，用户一句“帮我收菜”可触发可信市场发现、授权安装、对话配置、执行与结果闭环，无需手动进入插件列表。
- 三插件分别安装/启用/禁用；缺少一个后端时其他插件功能不受阻。
- 安装来源、完整性和兼容性检查失败时拒绝启用，保留已有可用配置。
- 对话设置每日 schedule，正确显示时区与下次执行时间；重启后计划保留，不把旧任务继续运行当作恢复。
- 验证计划修改/暂停/删除、同实例冲突、设备离线、登录失效及重复触发不会造成并发消费或无限补跑。
- 当前会话不能使用无归属实例；两个执行者控制同实例时正确拒绝。
- 状态与结果可追溯；stop 能触发实际后端停止并明确反馈。
- 取消、失败、消费策略及脱敏具有自动测试。

### 龙虾杀

- 以已有 Skill + CLI 打通一局；开局、状态、发言、投票、观战和结算可追踪。
- 用户只需要求“玩一局”，开局后 DSH 网页预览自动展示对应对局，无需复制链接；恢复参与不会误展示上一局，加载失败可重试或备用打开。
- 在测试事件与真实对局中确认重要事件可以触发必要 Agent 回合；采集延迟和错过截止原因。
- 检查重复事件、断线恢复、退出和跨局隔离，不重复创建 runtime。
- 不以胜负判断插件接入成功；不读取玩家不可见信息。

### Minecraft

- 在版本锁定、材料可获得的测试世界完成采木与石镐两条路径。
- 通过物品栏核验目标；取消移动/采集后不继续执行队列。
- 卡路、死亡和掉线能有限恢复或解释失败。

### MAA

- 用户可以仅通过对话完成受支持环境的连接配置、基建模板选择、关卡与资源策略设置，无需手改 JSON 或进入 MAA GUI；多设备须确认选择，连接失败不得标为配置成功。
- 运行时右侧自动展示对应设备的游戏画面，停止/掉线时显示状态，不将旧截图伪装成实时画面。
- 五类任务均有类型化封装、策略校验、回调与人工可核验结果。
- 测试关卡有限刷取、测试方案换班、信用领取、日常/邮件领取及一个肉鸽主题分别完成冒烟测试。
- 默认配置不吃药、不用源石、不购物、不抽卡；明确授权信用购物的路径另测。
- 停止长任务、连接失败、任务链错误及版本变化有测试覆盖。
- 肉鸽验收启动、进度、停止和可观察收益，不要求每局通关。

以上是待执行验收，不是已通过测试。真实账号测试由用户授权并在限制范围内进行。

## 12. 实施顺序与交付物

### 阶段 A：龙虾杀薄接入 + 最小 core

交付独立插件骨架、官方 Skill 加载与必要宿主适配、事件唤醒兼容性验证、DSH 网页预览自动观战与退出；不新增逐命令 CLI 工具。先证明能玩一局，再决定是否需要更复杂的事件调度器。

### 阶段 B：MAA 五类封装

交付库 worker、对话式首次配置与配置保存/修改、ADB 连接诊断、五类 schema、资源策略、右侧设备画面预览、回调解析和结果摘要；选择测试版本、基建方案和肉鸽主题，并验证收菜任务的 schedule 入口。

### 阶段 C：Minecraft 有界任务

交付 Mineflayer worker、状态/动作工具、采集合成模板、验证和故障路径。

### 阶段 D：三插件集成与发布

完成最小可信插件市场、目标驱动自动安装、持久化 schedule 与结果/失败记录，完成独立安装测试、资源锁、失败隔离、统一 UI、兼容矩阵、用户文档、许可证与分发检查。

以下为新增“可信插件市场、MAA 画面预览、持久化 schedule”之前的粗估，仅作历史参考，不作为当前完整 MVP 工期；须先核对 DSH 可复用能力再重估：龙虾杀薄接入 2–5 人日（已具备可用账号/CLI 且 DSH 调度路径可复用时）；MAA 五类封装 8–15 人日；Minecraft 基础闭环 8–15 人日；公共层、集成和回归 8–15 人日。部分工作可交叉，总工期不能简单相加；原型后重新评估。不包括高级策略、全版本支持、桌面安装器和商业化运维。

## 13. 评审前待确定项

1. DSH 固定版本与龙虾杀的实时事件调度路径。
2. 龙虾杀 CLI/Skill 版本、可用宿主标识和分发方式。
3. Minecraft 服务器与游戏版本、支持的生态组件和测试世界。
4. MAA 发布版本、资源版本、系统/模拟器/ADB 组合与 worker 实现方式。
5. MAA 测试基建方案、信用购物授权范围和首个肉鸽主题。
6. 确认固定 DSH 版本的网页预览调用与生命周期：龙虾杀默认展示官方观战页，MAA 的设备画面页与截图链路需验证。
7. 核对 DSH 插件市场/安装与 scheduler 的现有能力；缺失时补最小公共层，不能把设想当作框架已有功能。
8. 确定可信分发源、安装授权、依赖下载策略，以及本地常驻调度服务的生命周期与漏跑策略。

这些不阻止需求范围确立，但必须在实现和验收前落实。
